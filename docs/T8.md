# T8 — 저장, 복구 및 완성도

완료일: 2026-09-13

## 작업 범위

T7의 실제 SQLite·PostgreSQL Alembic 실습 상태를 IndexedDB에 체크포인트로 저장하고, 새로고침과 Worker 중단 뒤 마지막 성공 상태를 복원한다. 두 DB 모드의 파일과 실제 DB를 `WorkspaceArchiveV1` ZIP으로 내보내고 안전 검증·사용자 확인 후 새 workspace로 가져온다. CSP, 접근성, 초기 bundle 비용과 Chromium·Firefox·WebKit 회귀를 함께 마무리한다.

## 구현 결과

- 성공한 Alembic 명령, 저장된 파일, autogenerate revision 검토와 협업 통합 상태 뒤에 workspace 파일·실제 DB·lesson evidence·session UI metadata를 원자적으로 저장한다. 실패한 migration과 저장하지 않은 초안은 마지막 성공 checkpoint를 덮어쓰지 않는다.
- 새로고침 시 최대 네 workspace를 복원하고 실제 runtime inspect 결과로 revision graph, schema와 `alembic_version`을 다시 구성한다. timeout이나 Worker crash에서도 같은 checkpoint로 새 runtime을 만들며, 복구 실패는 자동 retry loop 없이 사용자에게 남긴다.
- SQLite는 실제 database file, PostgreSQL은 PGlite `dumpDataDir("gzip")` 결과를 checkpoint에 보관한다. PGlite는 고유 runtime ID의 IDBFS database에 복원하고 이전 instance는 비동기로 정리해 WebKit의 종료 중 connection과 충돌하지 않는다.
- Worker가 반환한 PGlite `Blob`은 IndexedDB 저장 전에 `ArrayBuffer`로 정규화한다. IndexedDB transaction 완료 handler는 transaction 생성 직후 등록해 WebKit의 빠른 완료 이벤트를 놓치지 않는다.
- `WorkspaceArchiveV1`을 실제 ZIP으로 구현했다. manifest, UTF-8 workspace 파일, SQLite file 또는 PGlite gzip dump와 lesson progress가 왕복한다. 가져온 workspace는 원본 ID를 사용하지 않고 새 ID로 격리한다.
- 압축 해제 전에 ZIP central directory를 검사해 traversal, 절대·역슬래시·중복 경로, 암호화·분할·ZIP64, entry 수, 개별·전체 압축 해제 크기를 제한한다. manifest와 DB mode/format, 선언되지 않은 entry, UTF-8도 runtime 생성 전에 재검증한다.
- Python 파일이 포함된 archive는 modal dialog에서 파일 목록과 내용을 먼저 보여준다. 사용자가 검토 checkbox를 확인하기 전에는 가져오기 버튼이 비활성화되고 runtime을 생성하지 않는다.
- document CSP는 same-origin script와 `wasm-unsafe-eval`만 허용한다. PGlite 0.5.8이 요구하는 `unsafe-eval`은 hash가 붙은 전용 Worker JS 응답에만 한정한다. COOP/COEP, CORP, nosniff와 referrer 정책을 유지한다.
- import dialog를 실제 modal dialog로 열어 focus 경계를 만들고, 기존 tab 방향키·Home/End, CodeMirror Tab 이탈, 좁은 화면 단일 패널 동작을 유지한다.
- ZIP 라이브러리는 import/export 시 동적으로 로드하고 checkpoint 명령 기록을 최근 20개로 제한한다.

## 현재 한계

- IndexedDB와 archive는 현재 브라우저·origin에만 존재하며 사용자 계정, cloud sync, 여러 기기 동기화를 제공하지 않는다.
- 저장하지 않은 CodeMirror 초안은 의도적으로 checkpoint에 넣지 않는다. `beforeunload` 경고는 제공하지만 강제 종료 뒤에는 복구되지 않는다.
- PGlite 0.5.8의 동적 PostgreSQL module loader가 직접 `eval`을 사용하므로 전용 Worker asset CSP에 좁은 예외가 필요하다. dependency가 제거하면 이 예외도 제거해야 한다.
- archive 검증은 파일 구조와 크기 위험을 막지만 Python migration의 의미나 안전성을 판정하지 않는다. 가져온 Python은 사용자 확인 뒤에도 브라우저 Worker 권한 안에서 임의 코드를 실행할 수 있다.
- 최대 네 runtime의 메모리 사용과 Pyodide/PGlite cold start 비용은 남아 있다. ZIP code splitting은 적용했지만 주 애플리케이션 bundle은 500 kB 경고 기준을 넘는다.

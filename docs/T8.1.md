# T8.1 — 개발 CSP 및 작업면 UX 개선

완료일: 2026-09-13

## 작업 범위

Vite 개발 서버가 production CSP를 그대로 사용해 React Fast Refresh script를 차단하던 문제를 환경별 nonce 정책으로 해결한다. 1280×720에서 코드, 실행 결과와 터미널을 한 viewport에 유지하는 IDE형 작업면을 만들고, 가이드 staging, 터미널 높이 저장, 편집기 최대화와 Workspace 관리 동선을 정리한다. Runtime protocol, Alembic 명령 API와 archive 형식은 변경하지 않는다.

## 구현 결과

- Vite 개발 서버 시작마다 임의 nonce를 만들고 `html.cspNonce`와 document CSP에 함께 적용했다. CodeMirror에는 HTML `csp-nonce` meta 값을 `EditorView.cspNonce`로 전달해 런타임 style도 같은 정책 안에서 허용한다. HMR용 `ws:`/`wss:`는 개발 `connect-src`에만 추가하고 production build·preview와 `_headers`는 기존 strict 정책을 유지했다.
- PGlite Worker 판별이 production hash asset과 개발 TypeScript Worker URL을 모두 인식한다. PGlite 0.5.8에 필요한 `unsafe-eval`은 해당 Worker 응답에만 존재하고 document와 다른 asset에는 허용하지 않는다.
- compact toolbar, 280px/48px 접이식 가이드, 코드·결과 2열과 하단 터미널 Dock으로 작업면을 재구성했다. 1280×720에서는 document 세로 스크롤을 제거하고 파일 트리, 편집기, 결과, 가이드, 터미널이 각자 내부 스크롤을 소유한다.
- 1280px 미만에서 가이드는 overlay로 동작한다. 850px 이하와 작은 높이 또는 확대 환경에서는 document 스크롤과 단일 패널 전환을 허용해 clipping보다 접근성을 우선한다.
- 터미널 Dock은 기본 176px이며 pointer drag와 ArrowUp/ArrowDown/Home/End로 132–320px 범위에서 조절한다. 높이는 선택적 `terminalDockHeight` session 값으로 저장하고 기존 session 및 범위 밖 값은 안전하게 보정한다.
- 가이드와 예시의 명령은 `onStageCommand`로 입력창을 채우고 선택·focus만 한다. 자동 실행하지 않으며 기존 form submit과 `RUN_COMMAND`를 통해서만 실행한다. 최신 결과를 Dock으로 자동 스크롤하고 짧은 `aria-live` 성공·실패 상태를 제공한다.
- 편집기 최대화는 같은 CodeMirror instance를 유지한 채 다른 작업면을 숨긴다. 버튼이나 Escape로 복원해 초안, undo history, 선택 파일과 스크롤 상태를 보존하며 최대화 여부는 새로고침 뒤 저장하지 않는다. WebKit에서도 CodeMirror의 이벤트 처리와 무관하게 동작하도록 Escape를 capture 단계에서 처리하고, 1280px 이상에서도 guide grid보다 최대화 열 규칙이 우선하도록 selector를 고정했다.
- 별도 DB 생성 모드를 제거하고 SQLite/PostgreSQL 생성 버튼이 해당 mode를 직접 생성한다. 내보내기, 가져오기, 추가 생성, capability와 위험한 초기화는 `Workspace 관리` 메뉴에 모으고 활성 DB mode를 toolbar badge로 분리했다.

## 현재 한계

- document 무스크롤 계약은 1280×720 이상, 100% 확대를 기준으로 한다. 작은 화면이나 높은 확대에서는 접근성을 위해 document 스크롤을 허용한다.
- 최대화는 브라우저 Fullscreen API가 아니라 앱 toolbar 아래 작업면 최대화이며 의도적으로 session에 저장하지 않는다.
- PGlite 0.5.8의 동적 PostgreSQL module loader는 직접 `eval`을 사용한다. 현재는 전용 Worker CSP에만 좁은 예외가 남으며 dependency가 이를 제거하면 함께 제거해야 한다.
- production의 주 애플리케이션 chunk는 500 kB 경고 기준을 넘지만 25 MiB 정적 파일 게이트는 통과한다. 추가 code splitting은 별도 성능 작업이다.
